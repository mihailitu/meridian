## Headline conclusions

1. **The phase-3 accounting/clock fixes are genuinely sound — but the data layer under the
   harness was never audited to the same standard.** Downloaded data is split-unadjusted
   (P0-1), every 7th day's bars are duplicated (P0-2), and the replay manifest silently
   resolves each symbol to the *wrong file* for the IS window (P0-3). The buy_hold
   calibration-to-the-cent is insensitive to all three (single fill, OHLC-preserving merge,
   volume-blind) — **it proved the accounting, not the data**.
2. **The `discovery_momentum` IS/OOS comparison in ROADMAP is structurally invalid**: due to
   P0-3, discovery-fed symbols never joined the IS replay at all but did join OOS. IS traded
   ~5 static symbols; OOS traded the discovered universe. The 1,506-vs-6,659 trade counts in
   the ROADMAP table are consistent with exactly this. The "DEAD — consistent" verdict may
   still be right, but the evidence for it is not.
3. **The live multi-process deployment has never truthfully worked and cannot work today.**
   Fills are never routed back to strategies (P1-1) — only the synchronous PaperBroker
   poll-after-submit hides this; the IBKR tick path drops essentially every market-hours tick
   (P0-4); and discovery scores never cross the API-process/strategy-process boundary (P1-3).
   Phase 4's stated success criterion ("live paper-trading capability") is not yet met for
   anything beyond the single-process mock/paper path the integration test covers.
4. **The API is an unauthenticated remote control bound to 0.0.0.0** (P0-5). Anyone on the
   LAN can enable strategies on the live runner or rewrite `config/default.yaml`.

## P0 — Invalidates results or defeats the platform's purpose

### P0-1. Historical data is split-unadjusted (Alpaca RAW) — fake ±80% gaps poison universe runs
- **Evidence**: `src/axtrade/fulltest/data.py:193-198` — `StockBarsRequest` passes no
  `adjustment` parameter; Alpaca defaults to `raw`. Verified empirically in
  `data/historical/`: TSCO opens 2024-12-20 at 0.20× prior close (real-world 5:1 split);
  KN/ESNT/MYGN show ~0.55-0.59 gap ratios in a 400-file sample.
- **Why it matters**: any strategy holding a splitting stock books a fake ±80% P&L move;
  momentum/volatility/trend screeners score the fake gap as an extreme signal and can feed
  the symbol to the gateway. Dozens of splits occur across an 18-month S&P 1500 window, so
  all discovery/universe results are contaminated. Dividends are also unadjusted with no
  cash credit — a systematic drag on long-holders including buy_hold on dividend payers.
- **Fix**: request `adjustment=Adjustment.ALL` (splits at minimum); re-download or
  post-adjust existing parquet; add a split-gap sanity check to the download path.

### P0-2. Weekly download chunks overlap — every 7th day's bars duplicated in parquet
- **Evidence**: `src/axtrade/fulltest/data.py:180-228` — chunk N ends `chunk_end 23:59:59`,
  chunk N+1 starts `chunk_start = chunk_end` at 00:00; no dedup before save. Verified:
  AAPL 2025-08 file has 36,596 duplicate-timestamp rows of 109,341.
- **Why it matters**: in fulltest the aggregator merges same-timestamp ticks into one bar
  (OHLC survives) but **doubles volume** on boundary days — distorting the pre-seeded daily
  universe volume, the VolumeScreener, and the C3 volume-participation cap. In the old CLI
  backtester the duplicates are *not* merged: strategies see every boundary bar twice and
  can double-trade it. The parquet's precomputed sma/rsi columns are also computed over the
  duplicated series.
- **Fix**: `drop_duplicates(subset="timestamp")` before saving; make chunk ends exclusive;
  dedup existing files in place.

### P0-3. Replay manifest keeps only the last file per symbol — discovery-fed symbols get zero IS data; IS/OOS structurally asymmetric
- **Evidence**: `src/axtrade/fulltest/replay_adapter.py:193-195` —
  `{fi["symbol"]: fi for fi in files}` keeps the last (filename-sorted → always the
  2025-08→2026-02 file). 1,438 of 1,446 symbols have two files. In an IS run
  (2024-08→2025-08), `_fast_forward_iterator` (`replay_adapter.py:234-242`) hits
  `ts >= end_dt` on the wrong file's first bar and returns None — the symbol never joins,
  silently, while the report still counts it as "fed" (`fulltest/discovery.py:123-124`).
  Static symbols get *both* files heaped (`replay_adapter.py:152-162`), so runs starting
  2025-08-01 replay that day twice, and the pre-seed's `ON CONFLICT DO NOTHING` makes the
  seeded row depend on thread completion order — a concrete mechanism for the observed
  run-to-run micro-nondeterminism.
- **Why it matters**: invalidates the discovery_momentum IS/OOS comparison (headline
  conclusion 2) and quietly biases any run over the earlier window.
- **Fix**: manifest lookup must select the file whose `[start_date, end_date]` covers the
  run window (and match interval); or consolidate to one file per symbol.

### P0-4. The IBKR tick path is dead end-to-end — three independent kills
- **Evidence**:
  (a) `gateway/ibkr.py:161` sets `volume=ticker.volume`; ib_insync's `Ticker.volume` is a
  **float**. `common/types.py:32` serializes `str(2417.0)` → `"2417.0"`;
  `common/messaging.py:158-159` parses `int(volume)` → `ValueError` → `_parse_tick` returns
  None (`:175-176`) → tick silently dropped and never acked. During market hours virtually
  every IBKR tick carries volume, so the aggregator drops ~100% of IBKR ticks.
  (b) `ticker.volume` is *cumulative day volume*, and `aggregator/engine.py:28-29` sums it
  per tick — even after (a) is fixed, bar volume would read ~50× day-volume.
  (c) `gateway/ibkr.py:184-185` calls `self._ib.sleep(0)` inside the running event loop on
  every 1-second idle timeout; ib_insync's `util.run` → `loop.run_until_complete` raises
  `RuntimeError: This event loop is already running`, killing the stream generator and
  sending the gateway supervisor into backoff every quiet second.
- **Why it matters**: the production adapter cannot produce a single bar. Phase 4's A3
  dynamic-subscribe fix (itself structurally sound) sits on top of a dead path — "live-IBKR
  validation remains" understates it. Kill (a) also poison-pills the consumer group PEL
  (unacked messages accumulate forever, see P2-7).
- **Fix**: parse `int(float(volume))` and ack-and-log unparseable messages; emit per-tick
  volume deltas from the adapter; delete the `ib.sleep(0)` call. Then unit-test the
  IBKR→aggregator round-trip with realistic ticker values (float/cumulative volume).

### P0-5. All mutating API endpoints are unauthenticated, and the API binds 0.0.0.0
- **Evidence**: `config/default.yaml:151` (`host: "0.0.0.0"`), no auth dependency anywhere
  in `api/`. `POST /api/strategies/{id}/enable|disable` (`routes/strategies.py:189,236`)
  publishes to the live control channel the StrategyRunner obeys;
  `POST /api/gateway/preference` (`routes/gateway.py:46`) rewrites `config/default.yaml`
  on disk; discovery scan/watchlist mutation endpoints likewise open.
- **Why it matters**: any host that can reach port 8000 can enable a trading strategy or
  mutate config/state. Today all strategies ship disabled, so the blast radius is
  "latent" — but this must land before any live-paper validation run on a real network.
- **Fix**: bind 127.0.0.1 by default; add an API-key/token dependency on every POST/DELETE
  route before ever exposing beyond localhost.

## P1 — Real bugs on the live or reporting path

### P1-1. Fills are never routed to strategies — async-broker (live IBKR) mode structurally cannot track positions
- **Evidence**: `strategies/runner.py:371-380` polls `get_position()` immediately after
  `submit_order` and updates the strategy cache from whatever the DB says *right then*.
  `OrderManager.on_fill` (`oms/manager.py:117`) has **zero registrations** in the codebase;
  `BaseStrategy.on_fill` is called only by the old `backtest/engine.py:94`. `stream:fills`
  (`manager.py:401`) has zero consumers. Found independently by two reviewers.
- **Failure**: with IBKRBroker, fills arrive after `submit_order` returns. Entry BUY → poll
  sees no position → strategy stays "flat" → re-enters every signal (per-strategy
  `max_positions` counts only settled positions, so in-flight orders bypass the cap). Exit
  SELL → poll still sees the open row → exit fires again next bar → naked short. Nothing
  ever corrects the cache.
- **Fix**: register a runner-level fill callback via `order_manager.on_fill` that re-reads
  the position and calls `strategy.update_position`/`on_fill` by strategy_id; count
  in-flight orders in `at_capacity()`. Treat the post-submit poll as a paper-mode fast path.

### P1-2. F10's async sibling race remains — SUBMITTED stamp can clobber a concurrent fill
- **Evidence**: `oms/manager.py:226-228` — status checked, then
  `order.status = SUBMITTED; await update(order)`. `OrderRepository.update` writes
  status/filled_quantity/avg_fill_price wholesale from the in-memory object. IBKR fills run
  as detached tasks (`oms/broker.py:632-636`) that can interleave at the await: read
  PENDING → fill task persists FILLED → manager's UPDATE lands, resetting the row to
  SUBMITTED with filled_quantity=0. Two concurrent partial-fill tasks can likewise lose an
  increment in `_on_broker_fill`'s read-modify-write (`manager.py:261-278`).
- **Fix**: conditional SQL (`UPDATE ... SET status='submitted' WHERE status='pending'`) or
  serialize per-order fill/status processing through a queue/lock. The synchronous paper
  path is correctly fixed (verified).

### P1-3. Discovery→trading bridge is inert in the real multi-process deployment
- **Evidence**: `DiscoveryService._discovered` is an in-process dict
  (`discovery/service.py:50`). The only live scanner runs inside the **API process**
  (`api/app.py:63-82`); the strategy-runner process constructs its own, never-scanned
  `DiscoveryService` (`strategies/runner.py:426-438`), so `discovery_momentum` sees score
  None for every symbol and force-closes any restored position. Works in fulltest only
  because everything shares one process (`fulltest/orchestrator.py:571-588`). Compounding:
  the API wires `DiscoveryRunner` with `ConfigSymbolProvider` (`api/app.py:77`), which
  returns only static gateway symbols, and `_feed_gateway` excludes static symbols — so
  live auto-subscribe can never add a symbol regardless.
- **Fix**: share discoveries via Redis or the existing `discovered_symbols` table, or run
  the scanner inside the strategy-runner process; swap in a real universe provider.

### P1-4. Broker-side cancels/rejections never propagate; no cancel API — open-order counter leaks until trading is permanently blocked
- **Evidence**: `oms/broker.py:576-587` `_on_order_status` only logs; nothing anywhere
  assigns `OrderStatus.CANCELLED`. `order_completed()` fires only on full fill or submit
  exception; `max_open_orders: 10` (`config/default.yaml:80`).
- **Failure**: 10 broker-side cancels/rejects (or never-completing partials) and
  `check_order` rejects everything for the life of the process.
- **Fix**: map IBKR terminal statuses to a manager callback that stamps CANCELLED and
  decrements; add `OrderManager.cancel_order`.

### P1-5. Alpaca quote handler fabricates prices from one-sided quotes — corrupt bars on the default adapter
- **Evidence**: `gateway/alpaca.py:133` — `price=(ask+bid)/2` even when one side is 0
  (lines 137-138 knowingly treat 0 as "no bid"). Quote mids and trade prints are also mixed
  into one tick stream (`:159-160`).
- **Failure**: IEX quotes are frequently one-sided pre/post-market; bid=0/ask=200 emits a
  tick at 100.00 → bar low/close poisoned → ATR/BB/regime/stops all wrong. This is the
  **default adapter** (`config/default.yaml:2`).
- **Fix**: skip quotes with a missing side; longer term, build bars from trades only.

### P1-6. Fresh `make infra` produces an incomplete schema — migrations have no runner in the documented path
- **Evidence**: `docker-compose.yml:24` mounts only `scripts/init-db.sql` (bars, positions,
  orders, fills). `strategy_state`, `discovered_symbols`, `screener_runs`,
  `regime_history` exist only in `scripts/migrations/`, applied only by `scripts/setup.sh`
  — not by the CLAUDE.md quickstart (`make dev` + `make infra`).
- **Failure**: on a fresh box, `GET /api/strategies` → `relation "strategy_state" does not
  exist` → 500; strategy enable/disable and discovery persistence broken.
- **Fix**: fold migrations into `docker-entrypoint-initdb.d` ordering, or run the
  migrations folder idempotently at service startup.

### P1-7. `POST /api/gateway/preference` destructively rewrites the tracked config file
- **Evidence**: `routes/gateway.py:64-73` — loads `config/default.yaml`, mutates one key,
  `yaml.dump`s the whole file back: all comments (including the per-strategy DEAD verdict
  annotations) destroyed; no file lock; unauthenticated (P0-5).
- **Fix**: store the preference in DB/memory (it already tracks `_preferred_adapter` and
  reports `requires_restart`), or write a separate runtime-override file.

### P1-8. No Redis stream trimming anywhere; consumer groups start at id="0"
- **Evidence**: `xadd` without `maxlen` (`common/messaging.py:55,268`; also
  `stream:fills`, `oms/manager.py:401` — which additionally has no consumer and is unprefixed
  by fulltest isolation). Groups created at `id="0"` (`messaging.py:92-93,305-306`).
- **Failure**: live-paper on Alpaca (trades+quotes) grows Redis by hundreds of MB/day until
  OOM kills the pipeline mid-session; any group re-creation replays the entire retained
  history as if live.
- **Fix**: `maxlen=~100_000, approximate=True` on publishes; create live groups at `"$"`
  (fulltest keeps `"0"` explicitly).

### P1-9. Live discovery eviction orphans open positions — and the fulltest comment says so
- **Evidence**: `discovery/runner.py:150-159` unsubscribes stale symbols; discovery_momentum
  exits only inside `on_bar`, which needs a bar for that symbol. Feed threshold
  (`min_score` 60) ≫ exit threshold (`score_decay_exit` 30): a symbol decaying 60→40 is
  unsubscribed while still held — bar flow stops, no exit can ever fire.
  `fulltest/discovery.py:136-139` explicitly refuses to evict for exactly this reason, so
  the harness never exercises the live path.
- **Fix**: never unsubscribe a symbol with an open position (check across strategies), or
  force-liquidate before eviction.

### P1-10. pairs strategy permanently wedges after one order rejection
- **Evidence**: `strategies/pairs.py:141-149` sets `_spread_direction` *before* submission;
  a rejection (swallowed in `runner.py:382-390`, strategy never told) leaves direction set
  with no position → `_check_entry` returns None forever, `_check_exit` never runs. Mirror
  case on the exit side leaves a position whose z-score exit is unreachable. Restart-restore
  has the same hole (`_spread_direction` resets to None with a live position).
- **Fix**: derive spread state from actual positions; commit state only on fill.

### P1-11. Dashboard money numbers are wrong or fabricated
- **Evidence**: (a) `api/routes/ws.py:104-112` — `cumulative_realized` sums `realized_pnl`
  over **open** positions only (closed positions dropped), then adds `daily_realized` on
  top — double-counted and partial. (b) `routes/analytics.py:26-54` and
  `routes/strategies.py:41-65` build every `TradeRecord` with `pnl=0`,
  `entry_time==exit_time` — so `/api/analytics/*` and `/api/strategies/{id}/performance`
  serve zeros/garbage the dashboard displays as real. (c) `usePnLHistory`
  (`web/ui/src/hooks/useApi.ts:150-187`) fabricates a flat $0 chart client-side because the
  endpoint was never built. Zero tests on any of it.
- **Fix**: reuse the fulltest FIFO analytics (`analytics/` package) for the API trade
  pairing; fix the cumulative formula; render "no data" instead of fabricated series.

### P1-12. Risk checks block position-closing orders (added 2026-07-17)
- **Evidence**: `oms/risk.py::check_order` applies the daily-loss halt, open-order cap,
  and order-size cap to every order, including sells that close an existing long. All
  strategies share one `RiskManager` and one `_daily_pnl` counter, so one strategy's
  losses can trip the halt and block every other strategy's *exits* for the rest of the
  day. Found while investigating P1-10: in the recorded `post-data-fixes` OOS leg, the
  tripped halt rejected the pairs close on 2025-08-01 (`orders` row: rejected SELL
  after a filled BUY), which wedged old pairs and froze the position for the remaining
  six months. A guard that prevents reducing exposure increases risk instead of capping
  it — in live trading this locks in losing positions exactly when the book is bleeding.
- **Fix**: reduce-only orders (sell with `qty <= held long qty`) bypass all pre-trade
  caps; sells that would flip short remain fully checked.

## P2 — Correctness risks and design flaws

### Harness realism (affects future strategy evaluations)
- **P2-1. Signal-bar-close fills grant stale prices across gaps**: a bar completes only when
  the symbol's *next* tick arrives (`aggregator/engine.py:126-128`); the runner then fills
  at that bar's close (`strategies/runner.py:319-325`, `oms/broker.py:196-226`). Across
  overnight/sparse gaps (common for discovery-fed small caps) the fill price is
  hours-to-a-day stale — systematically flattering mean-reversion/overnight styles.
  Fix: queue market orders, execute on next `update_price`.
- **P2-2. Extended-hours bars are fully tradable and define daily MTM closes**: no session
  filter in `data.py`; `fulltest/analytics.py:38-50` marks equity at the day's last
  (19:59 ET post-market) print. Overstates capacity, mismarks equity. Fix: RTH filter or
  16:00 session close for MTM; document the choice.
- **P2-3. Verdict P&L is commission-gross realized and excludes unrealized**:
  `report.py:183-194` sums `positions.realized_pnl` (commissions never deducted there,
  `oms/manager.py:352-380`) while PF in the same table is FIFO commission-net;
  `comparison.py:74` gates on the gross number. Mixed accounting bases inside one verdict.
  Fix: use FIFO net trades for verdict P&L; add unrealized as a column.
- **P2-4. The old CLI backtester diverges from the fixed harness**: same-bar close fills,
  unlimited oversell with cash credit (`backtest/broker.py:106-127`), double-replays P0-2's
  duplicate bars, minute-annualized Sharpe incomparable with fulltest's; plus
  `cli/backtest.py:55` crashes with `AttributeError` when `--strategy` is omitted.
  Fix: port fulltest semantics or deprecate the CLI path with a pointer.

### Pipeline robustness (live services)
- **P2-5. Bar completion is tick-driven only**: the day's last bar publishes at the next
  session's first tick with yesterday's timestamp; quiet symbols lag indefinitely
  (`aggregator/engine.py:122-138`, flush only at shutdown). Fix: periodic time-based flush.
- **P2-6. Late/out-of-order ticks contaminate the current bar**: earlier-bar ticks fall into
  the `else: update(tick)` branch (`engine.py:126-135`), overwriting close/low with old
  prices. Alpaca trades+quotes are not order-guaranteed. Fix: drop ticks older than the
  open bar.
- **P2-7. No PEL recovery in consumer groups**: read `">"` only, random consumer names per
  process, no XAUTOCLAIM/XPENDING anywhere; unparseable messages never acked. Crash =
  silently lost messages + unbounded PEL growth. Effectively at-most-once delivery dressed
  as at-least-once (`common/messaging.py:126-148,341-360`). Fix: stable consumer names +
  startup claim pass; ack-and-count parse failures.
- **P2-8. Shutdown flush publishes partial bars**: restart mid-minute → partial bar
  persisted+published, then the rebuilt bar publishes the same timestamp again and the
  upsert overwrites the DB row with a half-minute bar (`aggregator/service.py:131-134`,
  `common/db.py:99-107`). Fix: don't publish flushed partials (flag them), or reconstruct
  on start.
- **P2-9. Gateway degrades to a permanent no-op if Redis is down at startup** — logs
  `continuing_without_redis`, never retries, control subscriber (auto-subscribe) skipped
  too (`gateway/service.py:76-82,98`); per-tick publish failures never escalate to the
  supervisor. Fix: fail fast; route repeated publish failures to alerting.
- **P2-10. Alpaca stream thread can die silently / cross-loop queue handoff is broken**:
  `run_in_executor(None, self._stream.run)` runs handlers on a *different* event loop;
  `put_nowait` from that thread doesn't wake the main-loop getter (ticks drain only via the
  1s timeout poll), and the executor future has no done-callback — a subscription error
  stops tick flow forever with zero errors (`gateway/alpaca.py:118,141,207-216`).
  Fix: `call_soon_threadsafe` handoff + done-callback; add a tick-staleness watchdog in
  `GatewayService` (covers all adapters).
- **P2-11. Volatility regime classification is numerically degenerate on 1m bars**:
  20×1-minute returns annualized with `sqrt(252)` "assuming daily data" then scored against
  a VIX-calibrated constant (`indicators/regime.py:139-151`) → percentile 1-3 always →
  HIGH/EXTREME/BREAKOUT/BREAKDOWN unreachable. Every strategy branch on those states is
  dead code at runtime. Fix: scale by actual bar frequency or use a rolling empirical
  percentile.

### Risk & OMS gaps
- **P2-12. Daily-loss halt blocks exits too, globally, at $1000 on $100k in fulltest**:
  `oms/risk.py:93-98` applies to SELLs; one shared RiskManager for all strategies; the
  orchestrator never scales `max_daily_loss`. One −1% day freezes every strategy including
  their stop-losses until the next bar-date. Distorts fulltests; dangerous live. Fix:
  exempt position-reducing orders; scale the limit to capital.
- **P2-13. Risk check ignores position side — short netting inverted**: `risk.py:66-75`
  nets `current_qty ± order.quantity` regardless of `position.side`: buy-to-cover a short
  reads as doubling it (rejected); shorting more reads as flat (unchecked). Latent while
  long-only; it's the layer meant to catch exactly this. Fix: sign by side.
- **P2-14. Volume cap: a zero-volume bar bricks the symbol, and the feature is enabled
  nowhere**: `broker.py:209-218,337-338` — volume `0` is stored (only `None` skips), so
  cap = 0 rejects every order until a non-zero bar; and with `max_volume_participation: 0.0`
  shipped and no orchestrator override, the C3 feature is exercised by no run at all.
  Fix: treat 0 as unknown; pick a nonzero fulltest default if the cap was meant to bind.
- **P2-15. No crash recovery for risk/order state**: `_daily_pnl`/`_open_order_count` reset
  on restart (clears a daily-loss halt mid-day); IBKR `_order_map` is memory-only — on
  reconnect, in-flight orders' fills are dropped with a warning and rows stay SUBMITTED
  forever (`risk.py:39-40`, `broker.py:413,596-602`). Fix: rebuild from
  `orders WHERE status IN (pending, submitted)` + `reqExecutions` on connect.
- **P2-16. PaperBroker allows naked sells with full cash credit** (`broker.py:234-262`) and
  its internal `_update_position` is wrong for shorts/flips and keyed by symbol only
  (collides strategies) — currently dead code, but it's the "live parity" position source;
  fix or delete before anything trusts it. FIFO P&L queries also skip short round-trips
  entirely (`oms/repository.py:332-334,420-422`).

### Config & parity drift
- **P2-17. The yaml params were never the tested params**: the fulltest orchestrator builds
  strategy configs from code defaults + overrides only (`orchestrator.py:359-365`), so the
  phase-3 verdicts certify **code defaults**, while `config/default.yaml`'s strategy blocks
  (stops, lookbacks, z-thresholds) differ — pairs' yaml values are the ones its own code
  comment calls bad. The yaml's "DEAD (phase 3)" annotations certify configs that never ran.
  Fix: make the orchestrator consume the yaml strategy blocks, or annotate the yaml with the
  actually-tested values.
- **P2-18. `discovery.screeners` config block is entirely dead**: parsed
  (`common/config.py:368-375`) but every `DiscoveryService(...)` construction ignores it and
  uses hardcoded defaults (`service.py:54-63`); the yaml names don't even match registered
  screener names. Similarly `multi_timeframe` reads `rsi_min/rsi_max` while the yaml sets
  `rsi_oversold/rsi_overbought` (`multi_timeframe.py:41-42` vs `default.yaml:120-121`) —
  the exact bug class the yaml comment boasts of fixing for momentum. And
  `discovery.max_positions` is read by nothing.
- **P2-19. Discovery feed asymmetries**: live feeds `bullish_only=True`
  (`discovery/runner.py:123`) vs fulltest `False` (`fulltest/discovery.py:99`) —
